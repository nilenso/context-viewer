Core decisions

01

Run product in browser, without application backend

Decision: parsing, analysis state, visualization, and export live client-side.

Private conversation files do not pass through a Context Viewer server. Network disclosure occurs only when AI stages call configured provider.

Trade-off: simpler privacy boundary and hosting; API credentials and memory-heavy processing live in browser runtime.

02

Keep analysis engine headless

Decision: context-analyzer accepts caller-provided files/config and exposes typed operations; viewer adapts those operations to UI state.

Analyzer does not read environment variables or own React/Zustand state. This preserves reusable domain boundary and lets viewer own transport configuration.

Trade-off: explicit config threading and session adapters add ceremony but prevent UI concerns from entering domain pipeline.

03

Normalize all formats into one conversation model

Decision: downstream logic consumes canonical Conversation → Message → Part data, not source-specific records.

Pipeline state is authoritative aggregate for raw input, canonical conversation, dimension outputs, model configuration, and metrics.

Trade-off: parsers must preserve enough source meaning during normalization; downstream operations become format-agnostic.

04

Detect formats through parser registry

Decision: parsers implement common interface and register centrally.

Adding input format extends registry rather than branching pipeline. Parser detection happens before all semantic work.

Trade-off: detection order and parser confidence matter when formats overlap.

05

Use explicit imperative pipeline

Decision: Parse → Count Tokens → Segment → Identify → (Classify ∥ Color).

Control flow reads top-to-bottom. Stage functions return partial state; pipeline merges results, records errors, invokes interceptors, and captures metrics.

Trade-off: orchestration is deliberately concrete rather than generic DAG machinery. Easier auditability wins over arbitrary scheduling.

06

Compute deterministic baseline before AI

Decision: count tokens and derive static role.partType components without API dependency.

Viewer can expose structural context even without API key; AI stages enrich rather than define basic observability.

Trade-off: token counts use one chosen encoding and are estimates for models with different tokenizers.

07

Segment oversized text semantically

Decision: parts above 500-token default threshold are split by LLM; eligible parts run concurrently.

Classification sees smaller coherent units rather than forcing arbitrary character boundaries. Non-large parts pass through unchanged.

Trade-off: segmentation adds latency/cost and model nondeterminism. Current threshold is fixed default, and rerunning segmentation requires rebuilding from raw content.

thresholdparallel segmentation
08

Make taxonomies dimension-scoped

Decision: each dimension owns prompt, components, mapping, timeline, and colors.

One conversation can be interpreted through independent business taxonomies. Custom components override discovered components without changing raw conversation.

Trade-off: each active dimension multiplies AI work and state; targeted reprocessing prevents unrelated dimensions from rerunning.

09

Parallelize independent AI work

Decision: dimensions identify concurrently; classification and coloring run concurrently; classification uses parallel batches of 20 parts.

Wall execution follows slowest parallel path rather than sum of provider work.

Trade-off: lower elapsed latency can create request bursts. Fixed 20-part batching does not yet optimize for model context budget.

10

Preserve in-memory sessions for iteration

Decision: first analysis creates session; later calls mutate saved inputs and clear only affected outputs.

Idempotent stage checks determine what can remain. Input changes propagate through explicit dependency rules.

Trade-off: sessions are process-local and ephemeral; export is required for durable portability.

11

Store model choice per AI stage and session

Decision: segmentation, topic identification, classification, and coloring resolve models independently.

Conversation owns saved stage models. Group selection propagates group configuration to member sessions. Metrics record model actually used.

Trade-off: configured and last-used models can differ until explicit reprocessing; UI therefore separates configuration from call provenance.

stage model resolutionsave and propagate
12

Use OpenRouter-compatible IDs with conservative catalog

Decision: Luna 6 is default; Mini and Flash are available to four configurable stages; Jev is classification-only.

Viewer defaults to OpenRouter endpoint and chat protocol. Analyzer still accepts caller-supplied compatible URL and API mode.

Trade-off: small explicit catalog favors known behavior over arbitrary model strings. No automatic fallback hides provider/model failure.

model catalogprovider config
13

Separate saving configuration from executing work

Decision: dropdown changes persist immediately but do not silently spend money. User chooses “Re-run changed stages” or “Full re-run.”

Changed-stage mode compares configured model with last-used metric and clears dependent outputs. Full mode reparses original content and rebuilds pipeline.

Trade-off: extra user action prevents surprise calls but allows temporary configuration/provenance mismatch.

14

Measure both user wait and provider calls

Decision: workflow stores stage execution time, LLM elapsed span, per-call duration/model/tokens/cost, and total execution.

“LLM time” spans earliest API-call start through latest completion; parallel calls are not summed. Processing time is displayed as execution minus LLM span.

Trade-off: observed LLM time includes network, queue, and provider overhead; it is not pure model compute time.

15

Make analyzed state portable and validated

Decision: exports include canonical conversation, dimensions, model configuration, workflow metrics, summaries, and group metadata; imports validate with Zod.

Context Viewer export parser restores preprocessed state and bypasses expensive pipeline execution.

Trade-off: schema evolution requires backward-compatible optional fields and explicit restoration logic.

16

Keep groups virtual

Decision: group references member file IDs; it does not concatenate underlying conversations.

UI derives aggregate comparison while each member retains pipeline/session identity. Group-owned dimensions and model choices propagate to files.

Trade-off: aggregate UI must resolve member state repeatedly; avoids creating a second merged source of truth.

Group typegroup operations
17

Split domain, transient UI, and URL state

Decision: conversation store owns analyzed domain state; UI store owns dialogs/editing state; URL store owns navigable selection and view state.

Actions are application glue: they read stores, call analyzer, normalize results, and update stores.

Trade-off: cross-store actions require care, but domain data stays out of ephemeral controls and shareable state remains in URL.

conversation storeUI storeURL store
18

Keep summary and analysis outside main pipeline

Decision: narrative summary and context analysis are explicit on-demand operations.

Main pipeline produces structural component data. Optional narratives use default Luna model and can be regenerated independently.

Trade-off: fewer automatic calls and faster base workflow; summary/analysis have separate lifecycle and metrics concerns.
