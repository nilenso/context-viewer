How state and model configuration move through Context Viewer.

Detailed implementation map from React controls through Zustand, analyzer sessions, pipeline stage resolution, OpenRouter calls, and metrics back into UI. Source links are GitHub permalinks to exact code lines.

1. Mental model

Domain stateFrontend/UI stateConfigurationExternal API
User input │ ▼ React component ──intent──► viewer/stores/actions.ts │ │ │ subscribes ├── mutate Zustand conversation/group state │ ├── persist config into analyzer session │ └── call analyze({ sessionId, ...options }, config) ▼ │ Zustand stores ▼ ├── conversation-store analyzer in-memory Session ├── ui-store │ └── url-store ▼ runPipeline(ctx, aiConfig) │ stageModels[stage] ─────────┤ ▼ generateWithMetrics(...) │ ▼ OpenRouter-compatible API │ result + call metric ◄───────┘ │ ▼ interceptor copies PipelineState into Zustand │ ▼ React rerenders UI
Central distinction: Zustand contains UI-visible copies. Analyzer session contains authoritative mutable pipeline state for iteration. Actions deliberately update both when configuration must survive next analyzer call.

Analyzer state is copied into conversation store after every stage by pre/post interceptors. Pre marks stage as processing. Post spreads full current ctx into selected viewer conversation. Final analyzer result adds session identity and terminal status.

4. Initial upload: state passage end to end

Drop input. App passes files and loaded preset to processFileDrop.
Normalize import envelope. parseFileDropInput separates processable files, old IDs, and imported groups.
Create UI placeholders. Viewer allocates fresh file ID and inserts pending ViewerConversationState before analysis starts.
Resolve runtime AI config. Viewer reads module API key/environment and runtime model defaults through getAnalyzerConfig().
Call analyzer once per file. Each file receives independent analyzer session. Files process concurrently.
Create analyzer state. analyze() builds PipelineState from raw file and creates session.
Run stages. Pipeline invokes Parse, Count, Segment, Identify, then Classification and Coloring.
Publish progress. Interceptors copy current analyzer state to matching Zustand conversation after every stage.
Finalize. Viewer stores returned state, sessionId, normalized errors, and success/paused state.

6. Changing one stage model

Select option. Dropdown emits stage key plus OpenRouter model ID.
Determine owner. With selected ID, call saveStageModel. Without selection, update runtime defaults only.
Update group if selected. Merge changed stage into group.stageModels.
Resolve target files. Group targets all member IDs; file targets itself.
Update conversation copy. Merge changed stage into every target conversation’s stageModels.
Update analyzer session. For each target with sessionId, saveSessionStageModels writes cloned map into corresponding PipelineState.
Stop. No API call occurs. Configured and last-used model may now differ.
UI event └─ saveStageModel(id, "classifying-components", "typesafe/jev-router") ├─ group.stageModels[classifying] = Jev (if group selected) ├─ conversation.stageModels[classifying] = Jev (each target) └─ session.state.stageModels[classifying] = Jev (each target) No pipeline run. No cost. Existing workflow metric still describes previous call.

7. Re-run changed stages vs full re-run

Detect changed models

getChangedModelStages compares each configured conversation stage model against workflowMetrics.stages[stage].model. Any target mismatch marks stage changed. Missing historical metric also counts as mismatch when configured model exists.

Changed stageOutputs clearedStages that effectively call LLM
SegmentationCanonical conversation and deterministic outputs reset; all dimension outputs cleared.Segment → Identify → Classify + Color
Topic identificationDiscovered components, mapping, timeline, colors.Identify → Classify + Color
ClassificationMapping and timeline.Classification only; Coloring enters stage wrapper but skips with existing colors.
ColoringComponent colors.Coloring only.

Changed-stage flow

button: Re-run changed stages └─ getChangedModelStages(selected ID) └─ configured model != last metric model └─ reprocessStageModels(id, false) └─ analyze({ sessionId, reprocessStages }, getAnalyzerConfig()) └─ applyIterationInputs clears affected outputs └─ runPipeline sees missing outputs └─ generateWithMetrics resolves ctx.stageModels[stage]

Full rerun flow

button: Full re-run └─ reprocessStageModels(id, true) └─ analyze({ sessionId, fullReprocess: true }, config) └─ clear conversation + static outputs + every dimension output └─ rawContent remains authoritative └─ Parse → Count → Segment → Identify → Classify ∥ Color
Stage wrappers may appear in latest workflow even when their idempotent operation skips. Actual LLM calls are authoritative in metric.calls. Reprocessing clears only outputs required to force intended calls.

8. Group state and propagation

A group is configuration plus references, not combined analyzer session. Each member retains independent sessionId and PipelineState.

Group ├── id / name / title ├── fileIds[] ─────────► Conversation A ─► Session A │ ├──► Conversation B ─► Session B │ └──► Conversation C ─► Session C ├── dimensions / activeDimensions ├── stageModels └── summary / analysis fields App derives virtual conversation at render time: member messages + namespaced IDs + merged dimensions + originMap

Model edit on group updates group config, every member conversation copy, and every member analyzer session. Reprocessing uses Promise.all across members.

9. Metrics close configuration loop

Stage runner allocates metric. New record starts with execution/cost counters and empty calls.
Call wrapper timestamps request. Resolved model and start timestamp are captured immediately before generateText.
Call completion records provenance. End time, duration, model, tokens, and provider-reported cost flow through recordCall.
Pipeline aggregates stage. Stage LLM time spans earliest call start to latest end. Stage execution time covers complete stage function.
Interceptor publishes metric. Updated PipelineState.workflowMetrics enters conversation store.
UI compares desired vs actual. Configured model drives headings and changed-stage detection; per-call detail shows actual model used.

10. Import/export state transfer

Exports serialize domain state, stage configuration, metrics, and group metadata. API key and transient UI state are intentionally absent.

Export file ├── canonical conversation + metadata ├── dimensions and prompts ├── stageModels ├── workflowMetrics ├── optional summary / analysis └── groups with member references and group stageModels Import └─ Context Viewer parser validates metadata └─ pipeline detects parserName == "Context Viewer" └─ restorePreProcessedImport(...) └─ bypass normal AI pipeline └─ viewer remaps imported file IDs for groups
Security boundary: runtime API key is not part of PipelineState or export schema. Imported content needs current browser key only when user requests new AI work.

11. Summary and analysis state

Summary and analysis sit outside main pipeline. Viewer actions call dedicated analyzer operations with current conversation and prompt. Streamed chunks append into conversation/group state.

Generate summary ├─ selected conversation/group + saved prompt ├─ getAnalyzerConfig() base model (Luna default) ├─ summarize(...) └─ append chunks → aiSummary Generate analysis ├─ conversation component data + summary + prompt ├─ getAnalyzerConfig() base model (Luna default) ├─ analyzeContext(...) └─ append chunks → analysis

These operations do not use configurable four-stage dropdowns. Viewer catalog fixes summarizing and analyzing to Luna.

14. Invariants worth preserving

One owner per state kind

Domain result in conversation store; ephemeral editor state in UI store; navigation in URL store; iterative execution in analyzer session.

Configured ≠ executed

Configuration selects next call. Metrics report prior/actual calls. Never use metrics as implicit configuration.

No hidden spending

Changing model persists only. Explicit rerun starts provider calls.

Groups derive, members execute

Group owns shared config, but each file keeps independent session and pipeline state.

Raw input enables full rebuild

Full rerun clears derived data while retaining rawContent.

Provider failures stay visible

No automatic model fallback changes provenance behind user’s back.
